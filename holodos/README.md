# War1ouss / ЛЁХА — Twitch-бот и сайт

Рабочий сайт: https://holodos-bot-production.up.railway.app/

Общая система игрового баланса W для Twitch-канала `war1ouss` и сайта. Аккаунт бота в production — `bot_lehaAI` (Twitch логин регистронезависим). Проект размещён в Railway `leha-holodos`, а исходники развёрнуты из ветки `deploy/holodos-standalone` репозитория `1loneri/ribka`.

## Сейчас работает

- Вход на сайт через Twitch OAuth, профиль с реальными W, статистикой и заказами.
- Главная, казино, кейсы (визуальная страница, открытия пока отключены), дуэли, топ W, топ чата, магазин и профиль.
- Реальные данные для рейтинга, истории открытий и магазина; сайт и бот подключены к **одному** SQLite на постоянном томе Railway `/data/leha.sqlite`.
- `!холодос` — раз в 120 секунд на игрока; два одинаковых символа +5 W (27%), три одинаковых +20 W (0,5%), три короны 👑👑👑 +400 W (0,05%), остальные 72,45% — без награды. Эти результаты обрабатываются сервером.
- `!баланс`, `!топмонет`, `!статмонет`.
- Дуэли через чат/сайт с общей базой и кулдауном 150 секунд после завершения; ставки, банк и комиссия рассчитываются сервером.
- `!магазин`, `!купить`, `!заказ`: 240 VP — 18 000 W; 475 VP — 35 625 W; 1000 VP — 75 000 W. Заявки хранятся в БД, выдача VP **ручная**.
- Страница `/cases` готова визуально, но цены/вероятности/платные открытия не настроены — списаний W для кейсов нет.

## Запуск и безопасность

Используется Node 22, `tmi.js`, встроенный SQLite, HTTP-сервер в процессе Twitch-бота. Railway деплоит корневой `Dockerfile`, исходники в `holodos/src`.

Требуемые переменные: `BOT_USERNAME`, `TWITCH_CHANNEL`, `DB_PATH`, `PUBLIC_URL`, `ADMIN_PASSWORD`, `APP_SECRET`; также `ENABLE_DUELS=true` для дуэлей. Секреты хранить только в Railway Variables, не коммитить и не публиковать.

В Twitch Developer Console зарегистрировано приложение с callback `https://holodos-bot-production.up.railway.app/oauth/callback`, OAuth учитывает независимые права бота и входящих зрителей. Не запускайте второй независимый сервис с отдельной копией SQLite.

Проверка здоровья: `GET /health`. Наличие HTTP 200 ещё не означает, что браузерная вёрстка, OAuth и игровые сценарии протестированы — проверяйте логи и сценарии отдельно.

Полный рабочий план в [WEBSITE_ROADMAP.md](./WEBSITE_ROADMAP.md). Не меняйте игровые правила, магазин и базу ради визуальных правок.
